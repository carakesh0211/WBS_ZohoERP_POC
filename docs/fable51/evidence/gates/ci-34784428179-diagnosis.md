included" → `gotoScreen(page, 'audit-trail')` → `settleScreen()` line 231:

No screenshot was involved: the wait is for the shell's own "this screen rendered" flag, and neither

whole tablet-800 batch against one shared server, all green (2026-09-14).

In the failing test `analytics/manifest.js` was **never requested** and nothing after it either.
`router.js` imports the four manifests statically; a module graph whose one fetch never completes

request is made. The server served every request it received in 2–11 ms and logged no error in the
window (its one `ConnectionResetError` is at 22:28:47, a later test's page closing). The request was
lost between Chromium and uvicorn on the Windows runner and Chromium did not retry it; a lost module
fetch has no timeout and no retry in the browser.

## Classification

Intermittent, environmental, not reproducible on an idle machine: a release-gate reliability defect
of the CI harness, not an application, routing, fixture or assertion defect. Nothing in the
application is wrong for it; the same code passed the same gate twice before and every local run.
