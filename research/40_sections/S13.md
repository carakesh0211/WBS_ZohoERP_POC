## 13. Source-of-Truth Matrix

Every one of the 44 entities in the frozen entity registry appears exactly once below, with its system of record, data owner, creation system, update system, sync direction, integration method, external key, reconciliation rule, conflict handling and failure handling. The matrix is split into four domain tables because a single 44-row table with eleven columns is unreadable; the column set is identical in all four.

Cells reference short codes defined in §13.2 to §13.5 so that each cell states one precise thing rather than a paragraph. A coding agent should be able to implement any row without reading prose elsewhere in this document.

### 13.1 Column definitions

| Column | Means | Not to be confused with |
|---|---|---|
| System of record | The single system whose value is correct when two systems disagree | The system where the data is displayed |
| Data owner | The role from the frozen role registry accountable for the correctness of the data, not for operating the sync | The technical owner |
| Creation system | Where a new instance of the entity comes into existence | Where it is edited afterwards |
| Update system | Where subsequent changes originate. May be a different system from the creation system | The system of record |
| Sync direction | Which way values move across the Control Hub to Zoho ERP boundary | Whether the entity is visible in both |
| Integration method | The mechanism, code from §13.3 | The trigger |
| External key | The identifier that ties a Control Hub row to its Zoho ERP counterpart, or states that no counterpart exists | The primary key |
| Reconciliation rule | The check that proves the two sides agree, code from §13.4 | The sync itself |
| Conflict handling | What happens when the two sides disagree, code from §13.5 | Error handling |
| Failure handling | What happens when the mechanism itself fails, code from §13.6 | Conflict handling |

**Three ownership classes.** Every entity falls into exactly one.

| Class | Meaning | Count |
|---|---|---|
| CONTROL-OWNED | The Control Hub is the system of record. Zoho ERP either has no counterpart or holds only a coded reference. | 34 |
| ZOHO-OWNED | Zoho ERP is the system of record. The Control Hub holds a mirrored reference row used for control arithmetic and never edits the value. | 4 — Purchase Order Reference, PO Line, GRN Reference, Vendor Bill Reference |
| SHARED-BOUNDARY | Created in one system, updated in the other, or genuinely co-owned. Each such row states the split explicitly. | 6 — GRN Line, Bill Line, Actual Ledger, Asset Allocation, Attachment, Comment |

### 13.2 Sync direction values

| Value | Meaning |
|---|---|
| `LOCAL-ONLY` | The entity never crosses the boundary. No Zoho counterpart exists or is wanted. |
| `IN` | Zoho ERP to Control Hub only. The Control Hub never writes it back. |
| `OUT` | Control Hub to Zoho ERP only. |
| `BIDI` | Values move both ways, on different fields. The row states which fields go which way. |
| `OUT-THEN-IN` | The Control Hub creates the record in Zoho ERP, then treats Zoho as authoritative for its subsequent state. |

### 13.3 Integration method codes

| Code | Method | Evidence or note |
|---|---|---|
| `IM-00` | None. The entity does not cross the boundary. | — |
| `IM-01` | Incremental poll filtered on `last_modified_time`, with a stored Sync Cursor and a look-back window. | `GET /purchaseorders`, `GET /bills`, `GET /journals`, `GET /chartofaccounts` and `GET /vendorcredits` all accept `last_modified_time` `[source: Zoho ERP OpenAPI bundle openapi-all.zip, sha256 E95A0399… — verified 2026-08-05]` |
| `IM-02` | Full-refresh poll. Used where the list endpoint offers no last-modified filter. | `GET /fixedassets` list parameters are `organization_id`, `filter_by`, `sort_column`, `sort_order`, `page`, `per_page` only (OAS-09). `GET /contacts` and `GET /items` also expose no `last_modified_time`. |
| `IM-03` | Fetch by identifier only. No list or search endpoint exists, so identifiers must be discovered from a related document or captured at creation. | `purchasereceives` exposes only `POST`, `GET /{purchasereceive_id}`, `PUT /{purchasereceive_id}`, `DELETE /{purchasereceive_id}` (OAS-03) |
| `IM-04` | Outbound create or update over REST from the Control Hub. | e.g. `POST /purchaseorders`, `POST /journals`, `POST /fixedassets` |
| `IM-05` | UI-configured workflow webhook, production only, as an accelerator. Never the primary path. | Webhooks are configured in the Zoho ERP user interface with PUT, POST or DELETE and POST as the default, and an optional secret token of 12 to 50 alphanumeric characters `[source: https://www.zoho.com/en-in/erp/help/automation/workflow-actions/webhooks.html — verified 2026-08-05]` |
| `IM-06` | Manual configuration in the Zoho ERP user interface, then discovered by the connector. Cannot be provisioned by API. | There is no API to create a custom field definition (OAS-06) |
| `IM-07` | Derived locally in the Control Hub from other synced records. No direct Zoho counterpart to read. | e.g. open PO commitment, received-but-unbilled |

Pagination applies to every polled method: `per_page` defaults to 200 with a documented maximum of 200, and `page` defaults to 1 (OAS-08) `[source: Zoho ERP OpenAPI bundle openapi-all.zip, sha256 E95A0399… — verified 2026-08-05]`. Every request carries `organization_id` `[source: https://www.zoho.com/erp/api/v3/introduction/ — verified 2026-08-05]`.

### 13.4 Reconciliation rule codes

| Code | Rule | Frequency | Tolerance | Breach action |
|---|---|---|---|---|
| `RC-00` | Not reconciled. Local-only entity; integrity is enforced by database constraints. | n/a | n/a | n/a |
| `RC-01` | Count and checksum of key fields between Control Hub and Zoho ERP over the sync window. | Nightly | Zero on count | Reconciliation Pending; MSG-INT-006 |
| `RC-02` | Line-level value match from PO line to bill line on `purchaseorder_item_id`. | On every bill sync | Zero | MSG-PRC-004 if the bill exceeds the PO line |
| `RC-03` | Balance identity per PO line: ordered value = billed value + open commitment + released residual. | On every PO or bill sync | ₹0.00 | Reconciliation Pending; block capitalisation |
| `RC-04` | Exposure identity: Exposure = Open PO Commitment + Actual CWIP, at budget-head level and at project level; must equal the sum of the underlying ledger rows. | On every ledger write, and nightly | ₹0.00 | Halt availability checks for that budget head and alert Project Finance Controller |
| `RC-05` | Budget identity per version: Current Approved Budget = Original Budget + Approved Supplements - Approved Returns +/- Approved Transfers. | On every revision approval | ₹0.00 | Reject the revision; MSG-BUD-006 where applicable |
| `RC-06` | Orphan detection: a Zoho document carrying a CAPEX code with no matching Control Hub parent. | Nightly | Zero | Raise on SCR-27 for manual coding correction |
| `RC-07` | Coverage: every approved Purchase Request has zero or one Purchase Order Reference, and every Zoho purchase order carrying a CAPEX code has an approved Purchase Request. | Nightly | Zero | Raise on SCR-25; this is the control that detects a purchase order raised outside the process |
| `RC-08` | Full-refresh set comparison against the previous snapshot. | On each full refresh | Zero | Log the delta; no automatic action |
| `RC-09` | Received-but-unbilled identity per PO line: received quantity minus billed quantity is non-negative and equals the local unbilled-receipt bucket. | On every receipt or bill sync | Zero quantity | Reconciliation Pending; MSG-PRC-005 for ageing |
| `RC-10` | Capitalisation identity: total Asset Allocation equals the CWIP balance transferred; any difference must be an explicitly recorded write-off with a reason. | On capitalisation submission | ₹0.00 | Block; MSG-CAP-002 |
| `RC-11` | Configuration drift: discovered Zoho custom-field and reporting-tag definitions compared with the stored Field Mapping. | On connection health check | Zero | Mark the connection degraded; MSG-INT-001 style guidance |
| `RC-12` | Quota reconciliation: counted outbound calls against observed HTTP 429 responses and the plan's daily quota. | Hourly | n/a | Throttle the next window; MSG-INT-003 |

### 13.5 Conflict-handling codes

| Code | Policy | Applies to |
|---|---|---|
| `CH-00` | No conflict possible. Single writer. | Local-only entities with one creation path |
| `CH-01` | Control Hub wins. The Zoho value is corrected on the next outbound sync and the divergence is logged. | Coding fields the Control Hub owns on Zoho documents |
| `CH-02` | Zoho ERP wins. The Control Hub reference row is overwritten and the dependent ledger effects are recomputed. The Control Hub never edits the value. | Zoho-owned transaction values |
| `CH-03` | Split: Zoho wins on value, Control Hub wins on coding. If a Zoho line loses or changes its CAPEX code, WBS code or budget head, the Control Hub re-applies its own and raises MSG-INT-006. | Purchase order lines, bill lines, journal lines |
| `CH-04` | Neither side wins automatically. The row is set to Reconciliation Pending and worked on SCR-27 by the Project Finance Controller. | Value differences beyond tolerance |
| `CH-05` | Immutable. A conflicting change is rejected outright; a new version or revision is created instead. | Budget Version, Budget Revision, Approval Instance |
| `CH-06` | Append-only. Later records supersede earlier ones; nothing is updated or deleted. | All ledgers, all logs |
| `CH-07` | Approval-gated. Changing the value requires named-role approval and a recorded reason. | Zoho Organisation Mapping (MSG-INT-005), Approval Matrix, connection profile re-pointing |
| `CH-08` | Optimistic concurrency on the entity's version field. A stale write is rejected and the user is asked to reload. | Control-owned editable master and transaction records |

### 13.6 Failure-handling codes

| Code | Behaviour | User-visible message |
|---|---|---|
| `FH-00` | Not applicable. No integration path can fail. | — |
| `FH-01` | Retry with exponential backoff and jitter; after the configured attempt limit, move to a Dead-Letter Record. | MSG-INT-004 |
| `FH-02` | Fail the user action synchronously. Nothing is partially written; the transaction rolls back. | MSG-GEN-001 style, or the specific control message |
| `FH-03` | Skip and continue. Record in the Sync Log and re-attempt on the next cursor pass. Safe because the poll is idempotent. | None; visible on SCR-26 |
| `FH-04` | Pause this sync class only. Do **not** advance the Sync Cursor, so nothing is silently skipped. | Visible on SCR-38 |
| `FH-05` | Pause the whole connection and alert. Local operation is unaffected — the Control Hub continues to run stages L02 to L08 and L14 in full. | MSG-INT-002 |
| `FH-06` | Backoff and requeue on rate limit. No data is lost. | MSG-INT-003 |
| `FH-07` | Block the business action and route it to the exception path. | MSG-BUD-001 |
| `FH-08` | Degraded read: serve the last known good value, marked stale, with the as-of timestamp shown on screen. | Page-level strip |
| `FH-09` | Fail the setup step with a named remediation. The wizard cannot proceed past it. | MSG-INT-001 |

**Why capitalisation is anchored locally.** Fixed assets cannot be linked to a source project, purchase order or bill using documented fields, and the asset list cannot be polled incrementally because it exposes no `created_time` or `last_modified_time` (OAS-09) `[source: Zoho ERP OpenAPI bundle openapi-all.zip, sha256 E95A0399… — verified 2026-08-05]`. If the Asset Allocation row is lost, the traceability required by REQ-SEC-001 cannot be rebuilt from Zoho ERP. That makes Asset Allocation the highest-criticality backup target in the whole data model.

### 13.12 Entities with no Zoho ERP counterpart at all

Twenty-eight of the forty-four entities carry sync direction `LOCAL-ONLY` and never cross the boundary; a further two — Asset Allocation and the PO-line linkage held on GRN Line — cross outbound but have no readable counterpart on the Zoho side. The consequence is stated plainly because it drives the backup, retention and disaster-recovery requirements in §33 Non-Functional Requirements: **if the Control Hub database is lost, none of the following can be rebuilt from Zoho ERP.**

| Group | Entities | What is unrecoverable |
|---|---|---|
| Control values | Budget Version, Budget Line, Budget Revision, Budget Ledger, Commitment Ledger, Actual Ledger | Every budget, revision, commitment and exposure figure. Zoho ERP computes no commitment and holds no budget by head. |
| Governance | Approval Matrix, Approval Instance, Purchase Request Reference | The entire approval history and every Purchase Request, including the link from a purchase order back to the request that authorised it |
| Structure | WBS Element, Budget Head, Organisation | The whole WBS layer and the budget-head taxonomy |
| Capitalisation traceability | Capitalisation Request, Asset Allocation | Which CWIP funded which asset. Zoho holds no reverse link (OAS-09). |
| Receipt linkage | The PO-line linkage on GRN Line | Received-but-unbilled exposure |
| Integration state | Sync Cursor, Integration Event, Retry Queue, Dead-Letter Record and the log family | Sync position and in-flight work |
