## 4. Requirement Traceability Matrix

This section is the spine of the blueprint. It carries **one row for every one of the 107 requirements** registered in `C1_req_ids.json`, in registry order, and binds each requirement to (a) the SAP Project System capability that addresses the same control problem, (b) the capability our application must build, (c) the Zoho ERP dependency expressed as a specification-verified endpoint or an explicit *none*, (d) POC inclusion, and (e) the blueprint section where the design is written.

A coding agent should be able to read a single row and know what to build, what to call, and where the detailed rules live. Nothing in the matrix is illustrative; every row is present.

#### Four rules that govern every row

1. **Provenance discipline.** All 107 registered requirements carry `provenance = CLIENT-PDF`. The client document contains **no WBS hierarchy at all** — its budget structure is exactly two levels, CAPEX/CWIP project code and budget head (CONF-02). The WBS layer, the connector setup module, the 21-status model, the 17-position exposure matrix and the SAP-familiar UI mandate are **scope additions** carried under CONF-02, CONF-07, CONF-11, CONF-12 and CONF-06 respectively. They are **not** given REQ-IDs here and must never be presented as client-stated requirements. See §4.6.
2. **Endpoint discipline.** Every value in the Zoho ERP dependency column resolves to a row of `zoho_endpoint_inventory.json`, which was generated mechanically from Zoho's own OpenAPI bundle (78 modules, 869 operations, 561 paths, 163 scopes). A path absent from that bundle does not exist for the purposes of this blueprint. `NONE` means the requirement is satisfied entirely inside our application. `NONE - PROVEN ABSENT` means a search of all 78 modules, 561 paths and 163 scopes returned zero matches.
3. **SAP variant discipline.** Every SAP anchor in §4.2 names the SAP variant its source documents. SAP behaviour differs between classic on-premise SAP Project System, S/4HANA on-premise and S/4HANA Cloud; anchors are not interchangeable across variants.
4. **No silent resolution.** Where a requirement sits on top of a registered conflict, the conflict ID is named in the row or in §4.6. Conflicts are surfaced, never smoothed over.
